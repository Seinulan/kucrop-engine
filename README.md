KUCrop Engine

Веб-версия AquaCrop: считает сезон культуры по вашим файлам климата, культуры, почвы, грунтовых вод и агротехники. Пример для MVP, который идёт «из коробки»: станция Poltavka (Северо-Казахстанская область), подсолнечник, климат 2021–2024.

Физика: AquaCrop-OSPy 3.1.0, Python-реализация методики ФАО AquaCrop. Расчёт собирается из файлов AquaCrop, как в настольной программе.
ИИ: ExtraTrees, обученный на 1800 расчётах этой физики для 2024 года. Экспортирован в ONNX и выполняется в Node.js примерно за 0.01 мс, тогда как физике нужно около 0.2–0.5 с.

Запуск

```bash
pip install -r requirements-train.txt    aquacrop==3.1.0, numpy, pandas, scikit-learn, onnxruntime
npm install

python selfcheck.py                      1. все строки [OK]
python run_aquacrop.py --inspect         все файлы AquaCrop в проекте и что из них прочитано
node server.js                           2. http://localhost:3000 (без базы данных: без аккаунтов и истории)
python generate_model.py                 *по желанию, переобучить ИИ, ~7 мин
```

Годы и даты

Как в настольном AquaCrop, период расчёта задаёт климатический файл (`.CLI` со ссылками на `.Tnx`, `.ETo`, `.PLU`). Для встроенного Poltavka это 2021–2024, поэтому в «Симуляции» можно выбрать любой из этих годов и любую дату посева в их пределах. Загрузите свой `.CLI` с рядами за другие годы (хоть 1990, хоть 2026): список годов, допустимые даты и сезонные показатели (осадки, ETo, температура за апрель–сентябрь) подстроятся под файл сами. Дата вне периода файла отклоняется с понятным сообщением.

- Физика считает любой год из файла. Год влияет на результат погодой и концентрацией CO₂: её AquaCrop берёт из встроенной таблицы Мауна-Лоа по году посева.
- ИИ работает только для года и файлов обучения (2024, файлы из страницы «ИИ-модель»). Для остальных лет и файлов он не показывается, а сайт пишет причину. Чтобы ИИ работал для другого климата или года, его нужно переобучить: `python generate_model.py`.
- Регион известен только для встроенного примера. У загруженного климата показывается название станции из файла.
- Сезон считается внутри календарного года посева; культура, цикл которой уходит в следующий год, получит понятное сообщение.
- Файл уровня воды `.GWT` с датами, не пересекающимися с периодом расчёта, даёт предупреждение: берётся ближайшее значение из файла.

Интерфейс

SaaS-приложение: боковое меню, верхняя панель, отдельные страницы.

 Обзор — главные числа сезона (урожай AquaCrop и ИИ в т/га и ц/га, осадки, подъём от грунтовых вод), карточка урожая с «полосой сезона» (покрытие кроны по дням от посева до уборки), график кроны, сценарий расчёта.
 Симуляция — выбор файлов и условий (год и дата посева, глубина грунтовых вод, орошение, начальная влажность), результат и вкладки: крона, осадки, водный баланс, урожай, условия расчёта.
 История — сохранённые расчёты пользователя: станция и год, культура, дата посева, урожай AquaCrop и ИИ; расчёт можно открыть снова или удалить.
 Файлы AquaCrop — все .CLI/.CRO/.SOL/.GWT/.MAN и ряды погоды: выбрать, загрузить (можно перетащить), скачать, удалить свои. Свои файлы хранятся в аккаунте.
 ИИ-модель — точность (R², RMSE, по культурам), скорость против физики, важность признаков, файлы обучения, ограничения.
 Аккаунт — регистрация и вход по почте и паролю, профиль, выход.
 Настройки — тема и язык, состояние аккаунта.

Светлая и тёмная тема (плавный переход от кнопки, по умолчанию — как в системе). Языки RU / KZ / EN: переводится весь интерфейс и сообщения сервера (сводки файлов, ошибки, условия расчёта, причины, почему ИИ не показан). Выбор темы, языка, файлов и параметров запоминается в браузере.

Гость может считать встроенный пример без входа. Чтобы загружать свои файлы и сохранять расчёты, нужен аккаунт.

Бэкенд и база данных

Бэкенд: Node.js + Express, физику считает Python, данные хранит PostgreSQL (подходит Neon и любой другой). Сервер разбит на модули:

```
server.js                точка входа: собирает приложение
src/config.js            настройки и лимиты
src/messages.js          тексты сервера RU / KZ / EN, формат ошибок
src/python.js            запуск физики AquaCrop (очередь, таймаут), кеш справочника
src/ai.js                ИИ-модель (ONNX)
src/db.js                подключение к PostgreSQL и миграции
src/auth.js              аккаунты, пароли, сессии, ограничение попыток входа
src/storage.js           файлы AquaCrop (общие встроенные и свои у каждого пользователя)
src/history.js           история расчётов
src/routes/*.js          HTTP-маршруты
db/migrations/*.sql      схема базы; применяется сама при старте сервера
```

Таблицы (db/migrations/001_init.sql):

```
users        id, email (уникальна без учёта регистра), name, password_hash, created_at
sessions     token_hash, user_id -> users, created_at, expires_at
files        id, user_id -> users, name, kind, content (BYTEA), size_bytes, sha256, created_at, updated_at
simulations  id, user_id -> users, created_at, params (JSONB), station, crop, start_date, season_year,
             irrigated, yield_t_ha, ai_yield_t_ha, result (JSONB)
```

При удалении пользователя его сессии, файлы и расчёты удаляются каскадом.

API:

```
GET    /healthz                      жив ли сервер, загружен ли ИИ, подключена ли база
GET    /api/config                   библиотека файлов и сводки, значения по умолчанию, метрики ИИ, текущий пользователь
POST   /api/predict                  расчёт AquaCrop + прогноз ИИ; save: true сохраняет расчёт в историю
POST   /api/files                    загрузить файл AquaCrop (при подключённой базе нужен вход)
DELETE /api/files?id=                удалить свой файл
GET    /api/files/download?id=       скачать файл
POST   /api/auth/register            регистрация: email, password, name
POST   /api/auth/login               вход: email, password
POST   /api/auth/logout              выход
GET    /api/auth/me                  кто я, сколько файлов и расчётов
GET    /api/simulations              история расчётов
GET    /api/simulations/item?id=     сохранённый расчёт целиком
DELETE /api/simulations?id=          удалить расчёт; ?all=1 очищает историю
```

Безопасность. Пароль хранится только как scrypt-хеш с отдельной солью. Сессия — случайный токен в cookie (HttpOnly, SameSite=Lax, Secure под HTTPS, 30 дней); в базе лежит только SHA-256 токена. Неудачные попытки входа ограничены: 10 за 15 минут на почту. Каждый пользователь видит только свои файлы и расчёты. Все запросы к базе параметризованы.

Как хранятся файлы. Встроенные файлы примера лежат в коде и видны всем. Свои файлы пользователя лежат в таблице `files`. Python читает файлы с диска, поэтому сервер выкладывает их из базы в папку `user_files/u_<id>/`; после перезапуска папка восстанавливается из базы, так что на хостинге с временным диском файлы не теряются.

Без базы данных сервер тоже работает: аккаунтов и истории нет, загруженные файлы общие и лежат в `user_files/`. Если база недоступна, сервер всё равно запускается, гости считают встроенный пример, а вход отвечает «База данных недоступна».

Подключение базы (Neon)

1. На neon.com создать проект PostgreSQL. Регион лучше выбрать тот же, что у сервера.
2. Скопировать строку подключения (Connection string), вариант с пулом соединений (pooled). Она выглядит так: `postgresql://user:password@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require`.
3. На Render: сервис → Environment → добавить переменную `DATABASE_URL` с этой строкой → сохранить. Сервис перезапустится.
4. Проверить: `https://ваш-сайт/healthz` показывает `"database": true`, в логах Render есть строки «применена миграция 001_init.sql» и «База данных: подключена». Таблицы создаются сами.

Локально: `DATABASE_URL="postgresql://..." node server.js` (в PowerShell: `$env:DATABASE_URL="postgresql://..."; node server.js`). Строку подключения не добавляйте в репозиторий: в ней пароль.

Бесплатный план Neon: 1 ГБ на проект, база засыпает после 5 минут без запросов и просыпается при первом запросе (он идёт на секунду-другую дольше). Лимиты приложения: файл до 2 МБ, до 60 своих файлов и до 200 сохранённых расчётов на пользователя.

Деплой

В репозитории есть `Dockerfile` (Node 22 + Python + aquacrop 3.1.0). Один расчёт занимает около 0.5 с и около 75 МБ памяти, порт берётся из переменной `PORT`, проверка живости — `GET /healthz`. Проверка локально, если установлен Docker:

```bash
docker build -t kucrop .
docker run --rm -p 3000:7860 kucrop        # http://localhost:3000 , http://localhost:3000/healthz
```

Во всех бесплатных вариантах диск временный. С подключённой базой данных это не страшно: свои файлы и история лежат в базе. Без базы файлы, загруженные в `user_files/`, пропадают при перезапуске; встроенные файлы Poltavka лежат в образе и остаются.

Вариант 1. Render (бесплатно, для показа). На render.com: New → Web Service → подключить репозиторий GitHub (`Seinulan/kucrop-engine`, ветка `main`) → Language: Docker → Instance Type: Free → в Advanced указать Health Check Path `/healthz` → Create Web Service. Первая сборка занимает несколько минут; затем сайт открывается по адресу вида `https://kucrop.onrender.com` и сам пересобирается при каждом изменении в `main`. Ограничения бесплатного тарифа: после 15 минут без запросов сервис засыпает, пробуждение около минуты (откройте ссылку за несколько минут до показа), 750 бесплатных часов в месяц, диск временный. Мощность бесплатного экземпляра небольшая, поэтому расчёт может идти несколько секунд.

Вариант 2. Railway: New Project → Deploy from GitHub repo (Dockerfile находится сам) → Generate Domain. Бесплатный план даёт $1 кредита в месяц и до 0.5 ГБ памяти на сервис; когда кредит кончается, сервис останавливается.

Вариант 3. VPS, всегда онлайн: `docker build -t kucrop .` и `docker run -d --restart unless-stopped -p 80:7860 -v kucrop_user:/app/user_files kucrop`. Тогда загруженные файлы сохраняются в томе.

Вариант 4. С ноутбука на время показа: `node server.js` и временный туннель к порту 3000 (ngrok, cloudflared). Ссылка работает, пока ноутбук включён и программа запущена.

Hugging Face Spaces не подходит: с июля 2026 Docker-Space на бесплатном оборудовании требует подписку PRO.

Ограничения

1. ИИ воспроизводит физику для года и файлов обучения (2024). Прогнозом урожая на другие годы он не является. Основной расчёт физикой AquaCrop работает для любого года, который есть в климатическом файле.
2. `Wheat.CRO` - стандартная озимая пшеница ФАО (Италия, 197 дней). Для яровой пшеницы СКО загрузите откалиброванный `.CRO`.
3. Чего движок OSPy не моделирует: плодородие 15% и сорняки из `.MAN`, засолённость из `.GWT`. Поэтому урожай может быть выше, чем в настольном AquaCrop.
4. `Poltavka_0712.GWT`: в заголовке написано 1.70 м, а в данных 1.90 м. Используются данные; интерфейс подсвечивает это расхождение.
5. Старт с влажностью WP во всём профиле - крайний сценарий: по алгоритму ФАО сухая почва не проводит капиллярный подъём, поэтому урожай близок к нулю.
