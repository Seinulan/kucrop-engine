KUCrop Engine

Веб-версия AquaCrop: считает сезон культуры по вашим файлам климата, культуры, почвы, грунтовых вод и агротехники. Пример для MVP, который идёт «из коробки»: станция Poltavka (Северо-Казахстанская область), подсолнечник, климат 2021–2024.

Физика: AquaCrop-OSPy 3.1.0, Python-реализация методики ФАО AquaCrop. Расчёт собирается из файлов AquaCrop, как в настольной программе.
ИИ: ExtraTrees, обученный на 1800 расчётах этой физики для 2024 года. Экспортирован в ONNX и выполняется в Node.js примерно за 0.01 мс, тогда как физике нужно около 0.2–0.5 с.

Запуск

```bash
pip install -r requirements-train.txt    aquacrop==3.1.0, numpy, pandas, scikit-learn, onnxruntime
npm install

python selfcheck.py                      1. все строки [OK]
python run_aquacrop.py --inspect         все файлы AquaCrop в проекте и что из них прочитано
node server.js                           2. http://localhost:3000
python generate_model.py                 *по желанию, переобучить ИИ, ~7 мин
```

Годы и даты

Как в настольном AquaCrop, период расчёта задаёт климатический файл (`.CLI` со ссылками на `.Tnx`, `.ETo`, `.PLU`). Для встроенного Poltavka это 2021–2024, поэтому в «Симуляции» можно выбрать любой из этих годов и любую дату посева в их пределах. Загрузите свой `.CLI` с рядами за другие годы (хоть 1990, хоть 2026): список годов, допустимые даты и сезонные показатели (осадки, ETo, температура за апрель–сентябрь) подстроятся под файл сами. Дата вне периода файла отклоняется с понятным сообщением.

- Физика считает любой год из файла. Год влияет на результат погодой и концентрацией CO₂: её AquaCrop берёт из встроенной таблицы Мауна-Лоа по году посева.
- ИИ работает только для года и файлов обучения (2024, файлы из страницы «ИИ-модель»). Для остальных лет и файлов он не показывается, а сайт пишет причину. Чтобы ИИ работал для другого климата или года, его нужно переобучить: `python generate_model.py`.
- Регион известен только для встроенного примера. У загруженного климата показывается название станции из файла.
- Сезон считается внутри календарного года посева; культура, цикл которой уходит в следующий год, получит понятное сообщение.
- Файл уровня воды `.GWT` с датами, не пересекающимися с периодом расчёта, даёт предупреждение: берётся ближайшее значение из файла.

Интерфейс

SaaS-приложение: боковое меню, верхняя панель, отдельные страницы.

- Обзор — главные числа сезона (урожай AquaCrop и ИИ в т/га и ц/га, осадки, подъём от грунтовых вод), карточка урожая с «полосой сезона» (покрытие кроны по дням от посева до уборки), график кроны, сценарий расчёта.
- Симуляция — выбор файлов и условий (год и дата посева, глубина грунтовых вод, орошение, начальная влажность), результат и вкладки: крона, осадки, водный баланс, урожай, условия расчёта.
- Файлы AquaCrop — все .CLI/.CRO/.SOL/.GWT/.MAN и ряды погоды: выбрать, загрузить (можно перетащить), скачать, удалить свои.
- ИИ-модель — точность (R², RMSE, по культурам), скорость против физики, важность признаков, файлы обучения, ограничения.
- Настройки — тема и язык; раздел «Аккаунт» (вход появится позже).

Светлая и тёмная тема (плавный переход от кнопки, по умолчанию — как в системе). Языки RU / KZ / EN: переводится весь интерфейс и сообщения сервера (сводки файлов, ошибки, условия расчёта, причины, почему ИИ не показан). Выбор темы, языка, файлов и параметров запоминается в браузере.

Вход и база данных — следующий шаг. Сейчас все работают как «Гость»; в меню и настройках уже есть место под профиль, а сервер передаёт язык и параметры так, что добавить SQLite, вход и историю расчётов можно без переделки страниц.

Код: `i18n.py` — тексты сервера на трёх языках; `public/js/i18n.js` — тексты интерфейса; `public/js/app.js` — состояние, запросы, тема, язык, маршруты; `public/js/pages.js` — страницы; `public/js/charts.js` — графики; `public/css/app.css` — стили и обе темы. Сборка не нужна.

Деплой

В репозитории есть `Dockerfile` (Node 22 + Python + aquacrop 3.1.0). Один расчёт занимает около 0.5 с и около 75 МБ памяти (замер на этой же физике), порт берётся из переменной `PORT`, проверка живости — `GET /healthz`. Проверка локально, если установлен Docker:

```bash
docker build -t kucrop .
docker run --rm -p 3000:7860 kucrop        # http://localhost:3000 , http://localhost:3000/healthz
```

Во всех бесплатных вариантах диск временный: файлы, загруженные пользователями в `user_files/`, пропадают при перезапуске. Встроенные файлы Poltavka лежат в образе и остаются.

Вариант 1. Hugging Face Spaces (удобен для показа: бесплатно, без карты, 2 vCPU и 16 ГБ памяти; без трафика Space засыпает, первый заход после сна ждёт запуск)

1. На huggingface.co: New Space → SDK Docker → Blank → CPU basic (free) → имя, например `kucrop` → Create Space.
2. Загрузить проект. Способ А, в браузере: Space → Files → Add file → Upload files, перетащить содержимое папки проекта без `node_modules`, `.git`, `user_files`. Способ Б, из командной строки:

```bash
pip install -U huggingface_hub
hf auth login
hf upload ВАШ_ЛОГИН/kucrop . . --repo-type=space --exclude "node_modules/*" ".git/*" "__pycache__/*" "user_files/*"
```

3. Настройки Space уже записаны в начале этого `README.md` (`sdk: docker`, `app_port: 7860`). Дождаться сборки на вкладке Logs. Адрес: `https://ВАШ_ЛОГИН-kucrop.hf.space`.

Вариант 2. Render: New → Web Service → репозиторий GitHub → язык Docker → тип Free, Health Check Path `/healthz`. Бесплатный сервис засыпает после 15 минут без запросов, пробуждение около минуты, лимит 750 бесплатных часов в месяц, постоянных дисков нет. Вычислительные ресурсы бесплатного тарифа сильно меньше, чем у Hugging Face, поэтому расчёты будут медленнее.

Вариант 3. Railway: New Project → Deploy from GitHub repo (Dockerfile находится сам) → Generate Domain. Бесплатный план даёт $1 кредита в месяц и до 0.5 ГБ памяти на сервис; когда кредит кончается, сервис останавливается.

Вариант 4. VPS, всегда онлайн: `docker build -t kucrop .` и `docker run -d --restart unless-stopped -p 80:7860 -v kucrop_user:/app/user_files kucrop`. Тогда загруженные файлы сохраняются в томе.

Вариант 5. С ноутбука на время показа: `node server.js` и временный туннель к порту 3000 (ngrok, cloudflared). Ссылка работает, пока ноутбук включён и программа запущена.

Ограничения

1. ИИ воспроизводит физику для года и файлов обучения (2024). Прогнозом урожая на другие годы он не является. Основной расчёт физикой AquaCrop работает для любого года, который есть в климатическом файле.
2. `Wheat.CRO` - стандартная озимая пшеница ФАО (Италия, 197 дней). Для яровой пшеницы СКО загрузите откалиброванный `.CRO`.
3. Чего движок OSPy не моделирует: плодородие 15% и сорняки из `.MAN`, засолённость из `.GWT`. Поэтому урожай может быть выше, чем в настольном AquaCrop.
4. `Poltavka_0712.GWT`: в заголовке написано 1.70 м, а в данных 1.90 м. Используются данные; интерфейс подсвечивает это расхождение.
5. Старт с влажностью WP во всём профиле - крайний сценарий: по алгоритму ФАО сухая почва не проводит капиллярный подъём, поэтому урожай близок к нулю.
